# 企业产品智能客服 RAG 二次开发

## Goal

按已批准规划书完成阶段一至阶段七，优先复用 FastGPT 现有能力，只新增产品知识治理、客服权限边界和业务 API 适配。

## Requirements

- 在 FastGPT 现有数据集、训练队列、混合检索、Rerank、App、聊天、反馈、日志、费用、OpenAPI Key、权限和部署能力上完成二次开发，不复制已有能力。
- 建立产品大类、系列、型号、硬件版本、软件版本，并将产品型号绑定到现有 dataset。
- 知识正文、分块和向量仍由现有 collection 保存；新增引用式治理记录，支持草稿、待审、驳回、发布、下架以及禁止自审。
- 新增客服管理员、知识编辑、知识审核三个业务岗位；资源读写仍叠加 FastGPT 现有团队、dataset 和 app 权限。
- 建立客服项目和现有 App、OpenAPI Key 的引用绑定，Key 约束最高受众、启停、来源和限流；绑定 Key 不得绕过客服接口调用通用 completions。
- 对检索增加仅内部可用的 collection 白名单，并与 dataset、metadata filter、`forbid` 和团队范围求交集；异常时 fail-closed。
- 提供 `/api/customer-service/v1/products`、`chat`、`feedback`、`health`，复用现有流式聊天、引用、会话、反馈、usage 和日志。
- 提供站内客服入口、产品/版本选择、结构化追问、安全提示、低置信度和转人工卡片，浏览器不接触 OpenAPI Key。
- 支持 public、dealer、internal 三档受众和产品/版本过滤，危险、争议、投诉、人工请求及连续低置信度由服务端规则优先转人工。
- 完成阶段一至阶段七的环境验证、品牌裁剪、功能开发、资料导入/调优能力、部署升级回滚和验收材料。

## Constraints

- 不对知识库做物理分层；受众、产品和版本通过治理元数据及检索白名单实现逻辑隔离。
- 新增 API 必须使用共享 Zod/OpenAPI 合约、`parseApiInput` 和后端鉴权。
- 新增 MongoDB 索引必须使用 `defineIndex`，写操作支持可选 session，关键状态迁移使用条件更新或事务。
- 真实模型密钥、试点产品资料、生产域名和备份目标属于外部输入，不写入仓库；在缺少这些输入时用可替换配置、样例和自动化验证完成代码交付。
- 详细业务口径以仓库根目录的《智能客服RAG需求设计文档.md》《智能客服RAG功能开发文档.md》《智能客服RAG项目开发规划书.md》V1.1 为准。

## Acceptance Criteria

- [ ] 普通 FastGPT 数据集、检索、聊天和通用 Key 行为在未启用客服约束时保持兼容。
- [ ] 产品、版本、项目、知识治理和岗位绑定具备完整合约、服务、API、管理界面及权限测试。
- [ ] public/dealer/internal、型号、版本、发布状态、团队和 collection 白名单不能被客户端参数绕过。
- [ ] 客服聊天支持流式答案、引用、会话、反馈、幂等 requestId、服务端转人工和审计元数据。
- [ ] 已绑定客服项目的 Key 只能按绑定项目和最高受众使用，通用 completions 绕过被拒绝。
- [ ] 客服站内入口支持产品选择、追问、引用、反馈、恢复、转人工和移动端；浏览器端不暴露 Key。
- [ ] 提供资料模板、200 题题库格式、评测脚本/指标和三个试点产品的可重复导入流程。
- [ ] 提供无真实密钥的生产配置模板、迁移/升级/回滚/备份说明及健康检查。
- [ ] 局部测试持续通过；最终 typecheck、lint、全量测试和生产构建通过，或对上游既有失败给出可复现证据。

## V1.2 FastGPT 原生创建与智能客服标准模板

### 背景

用户确认 FastGPT 原生 Workflow 创建和工作台可以直接复用，但现有“问题分类 + 知识库”是通用演示模板，节点配置和提示词无法满足产品智能客服需求。

### 需求

- 应用列表提供“创建智能客服”入口，底层仍创建普通 Workflow App。
- 基于 `community-CQ` 的原生节点结构制作本地“企业产品智能客服标准模板”。
- 标准模板覆盖产品咨询、使用配置、故障排查、售后、问候、危险/人工和非业务分类。
- 知识检索默认使用混合检索、问题优化和 Rerank，并在无引用时直接追问。
- AI 提示词强制依据引用、禁止型号版本混用、资料不足不猜测、危险问题停止指导。
- 创建、编辑、调试、发布、日志和版本继续使用 FastGPT 原生功能。
- 客服 API 继续负责产品/版本/受众白名单、前置危险规则、后置置信度和连续低置信度计数。

### 验收

- [ ] 不新增 AppType、创建 API、编辑器、工作台或工作流节点。
- [ ] 新模板不包含原演示分类，并完整覆盖客服主要场景。
- [ ] 无引用不生成确定性答案，危险和人工问题进入专用分支。
- [ ] 用户可从“创建智能客服”创建模板并进入原生工作台。
- [ ] 普通 App 创建、现有 Workflow 和现网客服行为保持兼容。

详细方案以《智能客服RAG项目开发规划书.md》V1.2 第 16 章为准。2026-08-11 用户已批准本版规划，并已授权先制作智能客服标准工作流。

## V1.3 无 Rerank 先行交付

### 当前范围

- 当前部署不配置、不调用 Rerank 模型；模板显式关闭 Rerank，后续接入模型后再单独开启和调参。
- 保留混合检索与问题扩展，缩短送入回答模型的知识上下文，优先覆盖少量高相关片段。
- 普通回答控制在约 600 Token；价格表、型号表和长步骤按完整条目分页，禁止在一个条目中间截断，工作流保留 1200 Token 硬上限。
- 客服 API 识别标准工作流的问候、非业务、资料不足和人工/安全固定分支；固定回复不因没有引用而被错误改写，知识回答仍必须通过引用和置信度校验。
- 完成“创建智能客服”原生入口，继续创建普通 Workflow App 并进入原生工作台。

### 延后项

- Rerank 模型接入、权重和阈值调优。
- 依赖真实三产品资料、200 题题集和正式模型渠道的质量及性能验收。

## V1.4 智能客服产品化控制台

### 背景与目标

现有客服后端、治理规则和工作流已经可用，但管理端仍以一个综合技术页面暴露 App、Dataset、
Collection、OpenAPI Key 等内部对象。普通客服管理员需要在多个 FastGPT 原生页面之间跳转并手工
复制 ID，无法形成清晰的日常运营流程。本阶段在不复制 FastGPT 底层能力的前提下，新增业务化
控制台，将现有能力组织成一套可以独立使用和运维的智能客服产品。

### 需求

- 智能客服主导航默认进入业务控制台，在线咨询入口从控制台明确提供。
- 控制台使用统一侧边导航，包含总览、客服管理、知识中心、产品管理、审核中心和系统设置。
- 总览展示客服、产品型号、知识状态、待审核数量及关键待办，并提供常用操作入口。
- 客服创建采用分步向导，以名称、适用产品、服务范围、欢迎语和人工联系方式等业务字段完成
  配置；标准 Workflow App 由向导自动创建并绑定，普通管理员无需接触 App ID。
- 产品、知识、审核和客服列表使用业务名称展示关联关系，默认不显示数据库 ID。
- Dataset、Collection、App、Key 等原生资源继续由 FastGPT 保存和授权；确需底层操作时从系统
  设置进入“高级工作台”，旧管理页保留为兼容回退。
- 第一版不改检索、工作流运行、知识发布状态机和生产数据，不接入 Rerank。

### 验收标准

- [ ] 普通管理员可以从控制台看懂当前客服运行状态和待办，不需要打开旧综合管理页。
- [ ] 可以通过向导创建标准客服 App 和客服项目，过程中不手填 App ID。
- [ ] 客服、产品、知识和审核信息使用名称、状态及业务说明展示，默认不展示内部 ID。
- [ ] 所有既有管理能力仍可通过高级设置访问，原有 API 和生产客服问答保持兼容。
- [ ] 桌面端和移动端导航均默认进入新控制台，在线客服和高级工作台均有明确入口。

## V1.5 双前端产品闭环整改

### 背景

原需求第十章要求客户咨询端和管理运营端两套前端。V1.4 只有登录态多项目客服测试页和基础控制台，知识上传、对话运营及岗位维护仍依赖原生高级页面，尚不可作为完整产品交付。

### 需求

- 新增 `/customer-service/chat/{projectCode}` 正式客户入口，只加载指定启用项目，禁止项目枚举、浏览器 Key 和受众提权。
- 客户端覆盖欢迎语、推荐问题、系列/型号选择、文字与流式回答、引用、安全警告、点赞、点踩、问题未解决、人工入口和会话上下文。
- 管理端形成工作台、客服、知识、产品、审核、对话运营、团队与设置七个模块。
- 管理端覆盖全部对话和按项目/产品/型号/时间筛选，展示引用、Token/用量、耗时、反馈、无答案、未解决和转人工。
- 将资料上传、训练、治理、审核发布串成一条业务流程，并处理上传成功但未登记的恢复场景。
- 产品 Dataset 绑定变化后自动同步相关客服 Workflow 知识范围，提供就绪检查和失败重试。
- 按团队成员姓名分配、启停客服管理员、知识编辑和知识审核，维持职责互斥与禁止自审。
- 高频或未解决问题可以预填为知识草稿，但必须重新经过编辑和审核。

### 验收

- [ ] 原需求 10.1、10.2 逐项有可使用的页面和跨端验证。
- [ ] 客户端固定项目、无内部资源、无浏览器密钥且不能通过参数提权。
- [ ] 管理端日常操作不要求复制 App、Dataset、Collection 或 Key ID。
- [ ] 样例知识可以从管理端上传发布并被客户端命中和引用。
- [ ] 客户端“问题未解决”可以在管理端筛出并转为待整理草稿。
- [ ] Dataset 绑定变化可自动同步，失败可见、可重试且保留旧配置。
- [ ] 普通 FastGPT 功能保持兼容，Rerank 延后不阻塞本轮。

详细方案以根目录 V1.5 需求、功能和项目规划文档为准。用户已确认按两套前端整改。
